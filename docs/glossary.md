# 企业售后知识库 RAG 智能体：核心术语表

本术语表统一项目讨论、代码和文档中的含义。若同一词存在多种行业解释，以本文件为准。

## A

### ADR（Architecture Decision Record）

架构决策记录。用简短文档保存一个重要决策的背景、备选方案、最终选择及其后果，避免未来只知道“用了什么”却不知道“为什么”。

### Agent

能够根据当前状态选择下一步动作的系统。本项目中的 Agent 由 LangGraph 编排，模型可以辅助识别意图或生成参数，但权限、确认和关键业务顺序由确定性规则控制。

### AgentState

LangGraph 工作流在节点之间传递的结构化状态，可能包含消息、意图、用户上下文、检索结果、工具结果、待确认动作和错误。

## C

### Checkpoint

工作流状态的持久化快照，用于服务重启、人工确认或暂时中断后从正确位置恢复。不同会话通过 `thread_id` 隔离。

### Chroma

本项目第一版使用的本地向量数据库，负责保存文档分片向量及检索所需元数据。

### Chunk（文档分片）

从原始文档中切出的较小文本单元，是 Embedding 和检索的基本对象。每个分片必须能追溯到父文档、页码或章节。

### Chunk ID

分片的稳定唯一标识。它用于幂等写入、引用校验以及文档更新或删除后的索引同步。

### Context（上下文）

本项目中通常指传给聊天模型、用于回答当前问题的编号检索分片；它不同于完整对话历史，也不等于模型训练数据。

## D

### Document Loader

把 TXT、Markdown、PDF 等来源解析为统一文档表示的组件。

### Domain Model（领域模型）

用于准确表达业务概念及约束的数据结构，例如 `SourceDocument`、`DocumentChunk`、`TicketDraft`。

## E

### Embedding

把文本映射为数值向量的过程。语义相近的文本通常在向量空间中更接近。Embedding 模型负责表示文本，不负责生成面向用户的自然语言答案。

### Evaluation（评测）

使用固定数据集和指标检查系统质量。本项目区分检索评测与生成评测，并记录模型、分片、Top-K 和阈值等实验条件。

## F

### Fake Model

测试中使用的可预测模型替身。它不访问真实网络，用于稳定验证 Prompt、解析、路由和错误处理。

### Function Calling / Tool Calling

模型按照预定义 Schema 请求调用工具的机制。模型提出调用意图不等于获得执行权限，参数仍需校验，写操作仍需用户确认。

## G

### Grounding（依据约束）

要求生成答案以给定来源为依据。本项目中的知识回答只能使用实际检索并编号的 Context。

## H

### Hallucination（幻觉）

模型生成了看似合理但缺少可靠依据、与来源冲突或完全虚构的内容。引用、阈值和拒答可以降低风险，但不能保证绝对消除。

### Human-in-the-loop

在关键流程中由人进行审阅或决策。本项目创建工单前的明确确认属于人工介入。

## I

### Idempotency（幂等性）

相同操作重复执行时，不产生额外副作用的性质。重复导入不得产生重复分片；工单重试不得创建多个相同工单。

### Idempotency Key（幂等键）

标识一次逻辑写操作的稳定键。创建工单发生超时或重试时复用同一键，以识别重复请求。

### Intent（意图）

用户当前请求所属的任务类型。本项目第一版主要区分知识问答、设备或订单查询、创建工单以及未知意图。

### Interrupt

LangGraph 中暂停工作流并等待外部输入的机制。本项目用它实现工单创建前的人工确认。

## L

### LangChain

本项目用于模型、Prompt、Document Loader、Text Splitter、Embedding、Retriever、Tool 和输出解析等组件的框架。

### LangGraph

本项目用于显式定义 Agent 状态、节点、条件路由、循环限制、Interrupt、Checkpoint 和恢复执行的编排框架。

### LCEL（LangChain Expression Language）

组合 Prompt、模型和解析器等可运行组件的表达方式，常见形式是 `Prompt -> Model -> Parser`。

### LLM（Large Language Model）

大型语言模型。本项目通过 Provider 适配层调用通义千问聊天模型完成意图理解或答案生成。

### Low-confidence Branch（低置信度分支）

当检索结果没有达到可靠性要求时采用的明确流程，通常返回“不知道”、请求补充信息或建议人工核实，而不是强行生成答案。

## M

### Metadata（元数据）

描述数据的数据。文档分片的元数据包括来源、页码、标题、版本、分片序号和稳定 ID 等。

### MRR（Mean Reciprocal Rank）

平均倒数排名。对每个问题取第一个正确结果排名的倒数，再计算平均值，用于衡量正确结果是否排在前面。

## P

### PII（Personally Identifiable Information）

可以识别个人身份的信息。日志应避免记录完整联系方式、身份信息和不必要的用户上下文。

### Prompt

发送给模型的指令和输入结构。Prompt 可以约束模型行为，但不能代替权限检查、参数校验或确定性业务流程。

### Prompt Injection

用户或检索文档中的文本试图让模型忽略系统规则、泄露信息或调用越权工具的攻击方式。检索内容必须被视为不可信数据。

### Provider

对模型供应商能力的适配接口。业务代码依赖统一协议，不直接绑定通义千问的具体 SDK，从而便于测试和替换实现。

## R

### RAG（Retrieval-Augmented Generation）

检索增强生成。系统先从外部知识库检索相关资料，再把资料作为 Context 交给模型生成有依据的回答。

### Recall@K

前 K 个检索结果中是否包含目标来源的召回指标，用于回答“正确资料有没有被检索出来”。

### Reindex（重建索引）

根据当前原始资料重新生成分片、向量和元数据的过程，通常用于参数或 Embedding 模型发生变化时。

### Rerank（重排）

对初步召回结果再次评分并调整顺序的过程，用于把更相关的分片排在前面。

### Retriever（检索器）

接收查询并从向量库返回相关分片的组件，可组合 Top-K、元数据过滤、阈值和重排策略。

## S

### Schema

数据的字段、类型和约束定义。本项目使用 Pydantic 验证模型输出、工具参数和工具返回值。

### Similarity Score（相似度）

衡量查询向量与文档向量接近程度的数值。不同向量库和距离度量的数值方向可能不同，不能未经验证直接套用统一阈值。

### SourceDocument

规范化后的来源文档领域对象，包含稳定文档 ID、来源、校验值、版本和解析状态等信息。

### SQLite

本项目的关系型元数据存储，用于文档版本、导入任务、模拟业务数据，以及按具体实现选择保存 Checkpoint。

## T

### Text Splitter

按照标题、字符或其他规则把文档切成分片的组件。

### Thread ID

标识一条独立 Agent 会话的 ID，用于 Checkpoint 查询和不同会话之间的状态隔离。

### Token

模型处理文本时使用的基本计量单位。上下文长度、调用成本和部分延迟都与 Token 数量相关。

### Tool（工具）

具有明确输入和输出契约、可由 Agent 请求调用的函数。本项目工具包括用户、设备、订单查询和工单创建。

### Top-K

检索时返回得分最高的 K 个候选分片。K 过小可能漏掉资料，过大可能引入噪声并增加上下文成本。

## V

### Vector Database（向量数据库）

保存向量并支持相似度检索的数据库。本项目第一版选择 Chroma。

## 业务术语

### 模拟业务接口

为学习和演示而实现的本地 Repository 或 API。其用户、设备、订单和工单数据不是实时企业数据，必须在 README、界面和简历中清楚标注。

### 普通知识问答

只需要基于已导入售后资料回答、不需要访问个人业务数据的请求。

### 设备查询

依据设备标识读取模拟设备信息的只读操作，例如型号、激活或保修状态。

### 工单草稿

创建前收集并校验完成的信息集合。草稿没有产生业务写入，必须先展示给用户确认。

### 明确确认

用户在看到待提交动作摘要后，对该动作表达清晰同意。沉默、含糊回答、前序同意或对其他事项的肯定都不能当作本次写操作确认。

### 来源引用

回答中指向本次实际检索分片及其父文档位置的标识。引用不是模型自由生成的文本，必须通过程序校验。
